# Contributing to Diffy

Thanks for helping make Diffy better. This file covers how to commit, what to
run before committing, our AI policy, and what a pull request needs.

## Commit messages: conventional commits

Every commit on `main` uses [conventional commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <subject>
```

- `type` is one of `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
  `build`, `ci`, `chore`.
- `scope` is optional and names the area, e.g. `feat(diff-panel):`.
- The subject is imperative, lowercase, without a trailing period, and fits in
  about 72 characters.
- The body, wrapped at 72 columns, explains what and why rather than how, and
  references the issue or PR it relates to.

Examples:

```
feat(review): run reviews concurrently per PR
fix(diff-panel): keep the patch read-only when swapping PRs
docs: describe the mock feature in the README
```

Keep each commit to one thing. Commits made by the release workflow
(`Release vX.Y.Z`) are exempt.

## Before committing

Run the formatter and the linter, and make sure both are clean before every
commit:

```sh
cargo fmt
cargo clippy --all-targets
```

Run the tests as well:

```sh
cargo test
```

See the [Development](README.md#development) section of the README for what
the test suite covers.

## AI policy

LLM assistance is welcome, but a human stays in the loop. You must read,
understand, and review any AI-assisted code before committing it, and you
write the PR description and the replies to review comments yourself, not a
model. If you share context from a chat with an LLM in a PR or an issue,
quote the relevant part, disclose that it is AI-generated, and add your own
commentary on why it matters.

## Agents and ownership

You may use an AI agent (Mistral Vibe, Claude Code, …) to write code. When an
agent commits or creates a PR on your behalf:

- the agent is **never** a co-author: no `Co-Authored-By:` or `Generated by:`
  trailer for the agent, and the agent never sets itself as the commit or PR
  author;
- **you are the sole author and the full owner of everything the agent
  produced.** Agent-written code is your code: you review it, you understand
  it, and you are responsible for it, exactly as if you had typed it yourself.

## Pull requests

- Keep each PR to one thing; leave unrelated features and refactoring for
  another PR.
- Run Diffy and click through your change before opening the PR:
  `cargo run --release`, or `cargo run --release --features mock` to try it
  without GitHub or Claude credentials. With [bacon](https://dystroy.org/bacon/)
  installed, `bacon` (press `d` for its `dev` job, see `bacon.toml`) reruns the
  mock build on every change of `src/`.
- **Attach a screenshot or a video (screen recording or GIF) to the PR.** For
  changes to the window this is required, so reviewers can see the result
  without building it; describe what changed and how you tested it. For
  non-visual changes, include whatever shows the change works (test output,
  logs, benchmarks).
- Write the PR body yourself: what the PR does and why, and a link to the
  issue it fixes (`Fixes #123`).
